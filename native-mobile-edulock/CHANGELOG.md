- Feature & Architecture: **v1.3.57 (83) PENERAPAN MUTLAK SSOT PROVENANCE JADWAL, PENJINAKAN PENULIS LIAR MAINACTIVITY, DAN UNIT TEST REGRESI** (Rebuild 2026-09-21 09:25):
  1. **Akar Masalah Split-Brain & Penulis Liar Jadwal**:
     - `MainActivity.kt` bertindak sebagai penulis liar (*rogue writer*): saat UI dibuka, listener path lama `schools/{id}/schedule/weekdays` menimpa data jadwal sah dari admin yang baru saja ditulis oleh `MonitoringService`.
     - Rumus prioritas di service sebelumnya menggunakan heuristik cacat jumlah kunci `root.length() >= existing.length()`. Sekolah 5 hari kerja (5 kunci) dari admin modern kalah dan tertimpa oleh data lama 7 hari (7 kunci) karena 7 >= 5 bernilai true.
     - Cache jadwal tidak memiliki penanda asal data (*provenance tag*).
     - Tidak ada unit test otomatis untuk jadwal (`ExampleUnitTest` masih `2 + 2 = 4`).
  2. **Penerapan SSOT Provenance Tagging (`PreferencesManager.kt`)**:
     - Menambahkan key `KEY_WEEKDAY_SCHEDULE_SOURCE` dan properti `weekdayScheduleSource` dengan konstanta `SOURCE_ATTENDANCE_SCHEDULES` dan `SOURCE_LEGACY_WEEKDAYS`.
  3. **Penegakan Aturan Mutlak SSOT (`MonitoringService.kt`)**:
     - Path modern `school_settings/{id}/attendance/schedules` mencap sumber sebagai `SOURCE_ATTENDANCE_SCHEDULES`.
     - Path lama `schools/{id}/schedule/weekdays` **DIHARAMKAN MENIMPA** jika sumber data sudah `SOURCE_ATTENDANCE_SCHEDULES`.
  4. **Penjinakan Penulis Liar (`MainActivity.kt`)**:
     - `startWeekdayScheduleListener` di Activity dilarang menulis ke cache jika data sudah berstatus `SOURCE_ATTENDANCE_SCHEDULES`.
  5. **Penguatan Fallback Default Sabtu Libur (`SchoolScheduleManager.kt`)**:
     - Nilai fallback `"sat"` resmi default `false` (libur, sama seperti Minggu). Hari yang tidak ada di data admin sekolah 5 hari kerja tidak lagi disulap menjadi hari sekolah aktif.
     - `isEffectiveSchoolDayToday()` default `false` untuk Sabtu/Minggu jika jadwal tidak ditemukan.
  6. **Rangkaian Unit Test JUnit 4 (`SchoolScheduleManagerTest.kt`)**:
     - 5 test case komprehensif menguji Sabtu sekolah 5 hari, 6 hari, fallback cache blank, corrupt data, dan aturan penolakan overwrite SSOT. Seluruh test lulus 100%.
  7. **Status Build**: SHA256 `C60E3FE9F077A12A03F53F8D233974174CA56597189DC7F286DF4477AC494FCE` (3.975.511 bytes). Artefak: `EduLock_V2-1.3.57-83.apk` + `EduLock_V2-studentRelease.apk`.

- Feature & Hardening: **v1.3.55 (81) HARDENING RESPON REALTIME FCM & DEEP SLEEP WAKE DARI TIDUR PULAS (PARTIAL WAKELOCK + NOTIFIKASI INSTAN + ALARMMANAGER FALLBACK + PERPANJANGAN TTL 24 JAM)** (Rebuild 2026-09-18 10:27):
  1. **Akar Masalah Kegagalan Bangun Pasca 5 Hari Tidur Pulas**:
     - Pada perangkat yang tidak disentuh dan proteksi OFF selama 5 hari (khususnya Vivo V2030 / Android 12 FuntouchOS), socket TCP Firebase Realtime Database diputus total oleh Android Doze Mode.
     - WorkManager periodik 15 menit dibekukan oleh task killer OEM jika HP tidak pernah dibuka berhari-hari.
     - Sinyal FCM dari Web Admin sebelumnya memiliki TTL terlalu singkat (hanya 60 detik) sehingga langsung dihapus oleh server Google jika radio HP tidak sempat merespon dalam 1 menit.
     - Pemanggilan `startForegroundService` di latar belakang pada Android 12+ (API 31) melempar `ForegroundServiceStartNotAllowedException` tanpa ada mekanisme penyelamat darurat.
     - Mutasi variabel lokal `prefs.isProtectionActive = requestedState` sebelum database sync mematikan drift detection di `forceSyncProtectionStatus()`.
  2. **Perbaikan Web Admin (`edulockMasterSwitch.ts` & `edulockFindDevice.ts`)**:
     - Memperpanjang TTL FCM Master Switch dari 60 detik menjadi **24 jam (`24 * 60 * 60 * 1000` ms)** agar pesan proteksi tetap disimpan dan dikirimkan oleh Google saat perangkat online.
     - Memperpanjang TTL FCM Find Device dari 60 detik menjadi **5 menit (`5 * 60 * 1000` ms)**.
  3. **Penguatan EduLock Messaging Service (`EduLockMessagingService.kt`)**:
     - Menambahkan **Partial WakeLock 30 detik instan** saat `onMessageReceived` tiba agar CPU HP tidak langsung kembali tidur saat proses startup service berjalan.
     - Menampilkan **notifikasi sistem berprioritas tinggi** (`NotificationManager.IMPORTANCE_HIGH`) di `MonitoringChannel` seketika saat menerima perintah. Menghindari deprioritization FCM oleh Google Play Services dan langsung memberi tahu siswa di lock screen.
     - Fallback darurat Android 12+: jika `startForegroundService` dicegat OS, sistem langsung menjadwalkan `WatchdogAlarmReceiver.schedule(applicationContext, 0L)` untuk membangkitkan service menggunakan izin `AlarmManager.setAndAllowWhileIdle()`.
  4. **Penguatan Monitoring Service (`MonitoringService.kt`)**:
     - Menambahkan parameter `forceTriggerListener: Boolean = false` pada `forceSyncProtectionStatus()`. Saat dipanggil dari `ACTION_FCM_WAKE`, listener `protectionStatusListener.onDataChange(snap)` dipaksa berjalan penuh sehingga seluruh alur aktivasi proteksi (toast, notifikasi, `tryEnforceProtectionOnActivation()`, dan pemulihan overlay) dieksekusi tanpa bergantung pada drift detection.
