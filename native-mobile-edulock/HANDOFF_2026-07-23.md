## Status Selesai
- [x] Identifikasi APK terpasang: EduLock-Student.apk v1.3.0 (versionCode 26)
- [x] Diagnosa lokasi: Fused Provider 'grpc failed' → teratasi; lokasi/jarak normal
- [x] Bounce-back teratasi: Settings Aksesibilitas kini terbuka tanpa tertutup Lock screen (di luar jam sekolah)

## Masalah Aktif: AntiUninstallService crash loop di Vivo
- Setelah diaktifkan via ADB (`settings put secure enabled_accessibility_services`), service muncul di dumpsys accessibility sebagai:
  - `Enabled services:{com.sekolah.edulock/.AntiUninstallService}`
  - `Crashed services:{com.sekolah.edulock/.AntiUninstallService}`
- Logcat crash buffer menunjukkan **native crash (F DEBUG) berulang tiap ~0.5–1 detik**, terus-menerus (crash loop). Bukan exception Java biasa (tidak ada stack AndroidRuntime dengan nama kelas edulock — hanya backtrace native libandroid_runtime).
- Crash loop dihentikan sementara dengan:
  ```
  adb shell settings put secure enabled_accessibility_services ''
  adb shell settings put secure accessibility_enabled 0
  ```

## Dugaan Penyebab (urut kemungkinan)
1. **File SharedPreferences rusak**: `EduLockPrefs.xml` sempat di-push ADB dan berpotensi 0-byte/format salah → `getSharedPreferences` di `onServiceConnected`/`onCreate` melempar saat parse. Cek:
   `adb shell run-as com.sekolah.edulock ls -la /data/data/com.sekolah.edulock/shared_prefs/`
   → jika ada file 0 byte, hapus (rm) lalu force-stop app agar prefs dibuat ulang.
2. **Vivo Funtouch OS block**: Vivo agresif membunuh accessibility service yang diaktifkan non-manual. Pengaktifan **manual di perangkat** (Settings → Accessibility → EduLock Protection → ON, konfirmasi dialog Vivo) biasanya lolos.
3. Kode di `AntiUninstallService.onServiceConnected` yang mengakses resource/overlay tidak kompatibel Vivo.

## Langkah Berikutnya (sesi baru)
1. `adb shell run-as com.sekolah.edulock ls -la .../shared_prefs/` → deteksi file prefs 0-byte, hapus jika ada.
2. Baca `native-mobile-edulock/app/src/main/java/com/sekolah/edulock/AntiUninstallService.kt` → identifikasi kode di `onCreate`/`onServiceConnected` yang berisiko (prefs, WindowManager, performGlobalAction).
3. Ambil logcat terfilter saat mengaktifkan manual:
   `adb logcat | grep -i edulock` (dan `-b system`) untuk menangkap exception sebelum native crash.
4. Tambahkan guard: try-catch + inisialisasi tertunda (Handler.postDelayed) di `onServiceConnected` agar kompatibel Vivo; build APK baru; uji pengaktifan manual.

## Update: Perbaikan Dialog Loop & WindowLeaked — SELESAI & TERVERIFIKASI
- Akar masalah: `MainActivity.checkAndEnforceAccessibilityService()` membuat dialog berulang tanpa dismiss saat activity ke background → `WindowLeaked` (bukan crash native AntiUninstallService).
- Perbaikan di `MainActivity.kt`:
  1. Guard `isFinishing || isDestroyed` sebelum membuat dialog.
  2. Throttle `lastAccessibilityDialogShownAt` (3 detik) memutus loop cepat.
  3. `onPause()` me-dismiss semua dialog (accessibility/permission/admin/overlay/uninstall).
- Verifikasi (EduLock-studentDebug.apk, live ADB logcat): 0 WindowLeaked, 0 crash loop, aplikasi stabil.
- Langkah berikut: AntiUninstallService yang dinonaktifkan sementara dapat diaktifkan kembali secara bertahap.
